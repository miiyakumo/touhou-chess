# 幻翼合体：空袭升级｜实施路线图

## 总体策略

采用“先战斗验证、后素材扩展、最后数值打磨”的顺序。第一阶段只做一个小而完整的战斗切片，不先制作大量怪物或界面。切片通过后，再把部件组合系统扩展到完整怪物库。

技术落地采用 **Phaser 3 + TypeScript + Vite**。当前 `index.html` 是视觉和交互概念原型，保留作参考，不继续在单文件上叠加正式战斗逻辑。

## 阶段 0：项目迁移与工程底座

**目标**：建立可长期维护的项目结构。

工作项：

- 初始化 Vite + TypeScript + Phaser 3。
- 建立 `src/scenes`、`src/entities`、`src/systems`、`src/data`、`src/assets`、`src/ui` 目录。
- 设置固定逻辑分辨率和响应式缩放。
- 接入基本场景：Boot、Preload、Menu、Battle、Result。
- 保留当前原型作为设计参考，不直接复用其单文件实现。

完成标准：空项目可以进入战斗场景，桌面和移动浏览器都能正确缩放。

## 阶段 1：最小战斗切片

**目标**：证明放风筝本身好玩。

只加入：

- 玩家方块飞行器。
- WASD / 方向键移动。
- 移动端拖动或虚拟摇杆。
- 自动锁定最近敌人。
- 自动三叉戟攻击。
- 生命、碰撞、受伤、死亡和重开。
- 幻翼一种敌人。
- 简单末地虚空背景。

完成标准：玩家不操作攻击，只靠移动可以击杀幻翼并存活至少两分钟；停在原地会明显受伤。

## 阶段 2：第一条合体链

**目标**：验证“新部件 = 新行为”。

按顺序实现：

1. 幻翼：接近和俯冲。
2. 小僵尸骑士·幻翼：保留俯冲，追加挥砍和短冲锋。
3. 苦力怕·幻翼：保留接近，追加蓄力爆炸。

每种新形态首次作为 Boss，之后以精英或普通怪出现。

完成标准：玩家能从外观和动作分辨三个部件；所有强攻击有清晰预警；旧 Boss 降级后不会遮挡新 Boss 的存在感。

## 阶段 3：部件化敌人系统

**目标**：让创意组合可以通过配置扩展，而不是每只怪物单独写逻辑。

建立以下数据结构：

- `BaseBody`：底盘、移动方式、基础体型。
- `Rider`：骑乘者和近战行为。
- `AttackModule`：苦力怕、凋零头、烟花等攻击模块。
- `Modifier`：闪电、末影、冰霜、蛛网等强化模块。
- `EnemyRecipe`：部件组合、名称、倍率、Boss 阶段。

攻击由模块注册并按阶段轮流触发。组合只负责装配模块，不复制技能代码。

完成标准：新增一种组合只需添加配置和素材，不需要修改战斗主循环。

## 阶段 4：远程与高阶能力

**目标**：增加敌人的远程进展，同时保留躲避空间。

按风险递增实现：

1. 烟花：直线冲撞和散射烟花。
2. 闪电苦力怕：爆炸圈和落雷标记。
3. 凋零：三向骷髅弹。
4. 监守者：蓄力直线音波。
5. 终焉合体：按阶段轮流使用前述能力。

完成标准：同屏出现多个能力时，玩家仍能看清攻击来源和安全区域；所有高伤害技能存在反应窗口。

## 阶段 5：正式 MC 化素材

**目标**：让素材从概念占位变成统一美术资产。

顺序：

1. 先绘制玩家飞行器和三叉戟弹。
2. 再绘制幻翼、僵尸、苦力怕三个第一阶段部件。
3. 接入受击、俯冲、爆炸和升级动画。
4. 扩展烟花、凋零和监守者部件。
5. 最后制作背景、掉落物、粒子和 Boss 登场效果。

每个素材以独立部件保存，统一等距角度、像素网格和阴影方向。优先做能复用的部件，不先做一次性完整插画。

完成标准：移除所有 Emoji 和通用占位图形；不看文字也能认出主要 Minecraft 生物部件。

## 阶段 6：成长与数值膨胀

**目标**：形成“玩家变强，但敌人膨胀更快”的节奏。

实现：

- 经验球和升级。
- 自动增加伤害、射速、弹道或生命。
- 敌人阶段倍率、波次倍率和 Boss 倍率。
- Boss → 精英 → 普通怪的降级规则。
- 暴击数字、经验聚拢、掉落喷出和升级闪光。

数值先使用简单倍率，试玩后再调；不要一开始做复杂装备词条和技能树。

完成标准：前期 Boss 在后续确实变成可快速击杀的小怪；新 Boss 的威胁来自新能力和更高倍率，而不是只有血条变厚。

## 阶段 7：界面与反馈收束

**目标**：保留廉价页游的视觉冲击，但不靠大量文字。

保留：

- 生命、经验、等级、波次和 Boss 血条。
- 金色粗边框、高饱和附魔色。
- 巨大伤害数字、闪光、爆炸和装备掉落。
- 简短的 Boss 名称和升级数字。

删除：

- 假聊天频道。
- 活动、充值和长公告。
- 复杂按钮组和技能快捷栏。
- 与战斗无关的说明文字。

完成标准：玩家主要通过画面和数字理解状态，不需要阅读段落文本。

## 阶段 8：测试与交付

测试顺序：

1. 单敌人移动和命中。
2. 三种能力预警是否可见。
3. 多敌人同屏是否仍可辨认。
4. Boss 降级是否正确触发。
5. 数值长时间运行是否溢出。
6. 死亡、重开和本地记录。
7. 移动端拖动和不同窗口尺寸。
8. 构建产物和离线打开。

最终交付：

- 可运行网页构建产物。
- TypeScript 源码。
- MC 同人素材和素材说明。
- 玩法、操作和已知问题文档。
- 一个完整的第一阶段战斗切片。

## 推荐执行节奏

- 第 1–2 天：阶段 0。
- 第 3–4 天：阶段 1。
- 第 5–7 天：阶段 2。
- 第 8–10 天：阶段 3。
- 第 11–14 天：阶段 4 和阶段 5 的第一批素材。
- 第 15–16 天：阶段 6。
- 第 17 天：阶段 7。
- 第 18–20 天：阶段 8 和第一版打包。

这是一个单人、非商业、简单网页项目的估算。若素材全部自行绘制，素材质量和动画数量会是最主要的时间变量。
