# 人类杀 v0.4.2 联机维护说明

## 结构与数据流

`src/` 保留已有发布包的模块结构，使用 CommonJS；`scripts/build.mjs` 检查依赖并将模块封装到 `hx.html`。发布只复制这一个生成入口，`public/` 不得存在同名文件。

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 信令、WebRTC | `src/net/native-peer.js`、`src/net/peer.js` | PeerServer 兼容信令、RTC 建联、分片、取消 |
| 联机协议 | `src/net/protocol.js` | 客户端命令和完整房间视图的运行时白名单 |
| 房主会话 | `src/net/host-session.js` | 把连接绑定到成员、限制流量、发送持久化回执和私有视图 |
| 客户会话 | `src/net/client-session.js` | 本机待确认记录、同一命令重试、ACK Promise、终态 |
| 房间权威 | `src/room/authority.js`、`src/room/store.js` | 串行事务、规则判定、IndexedDB 存档、成员身份 |
| 页面生命周期 | `src/ui/controller.js` | 创建、恢复、重新连接、离房、废弃旧异步结果 |
| 显示与语音 | `src/ui/app.js`、`src/net/voice.js` | 文本转义、聊天草稿、麦克风生命周期、房主语音混音 |

信令 WebSocket 传递 SDP 和 ICE。游戏命令、房间视图和发言状态走 WebRTC 数据通道；音频走 RTC 媒体轨道。已建立的数据通道和音频不依赖信令 WebSocket 持续在线。房主承担规则权威、存档和语音转发；房主离线时仍需要恢复并由玩家重连。

## v3 命令与回执

每个成员持久化一个随机 `commandGeneration`、已接受的 `commandSeq` 和一个 `lastReceipt`。发给本人的视图包含 `commandGeneration` 与 `nextCommandSeq`，不包含成员凭证或其他成员的私有状态。

客户端命令具有 `id`、`roomId`、`matchId`、`epoch`、`generation`、`commandSeq`、`intent`。客户端在发送前先保存原信封，同一时间只保留一项待确认操作。

房主在串行事务内部重新检查成员 token、generation 和连接所有权。检查发生在实际执行时，因此排队期间踢人、换座位或替换连接，不能把旧命令变成新成员的操作。

- 新命令序号必须严格为已接受序号加一。
- 同一个最后回执的序号、ID 和内容完全相同，返回原回执，不再次保存或执行。
- 更旧的序号拒绝；同序号更换内容拒绝；跳过序号拒绝。
- 只有 `store.save` 成功后才提交内存状态、广播结果和发送 ACK。
- `SAVE_ERROR`、`HOST_CHANGED`、`RATE_LIMIT`、`BUSY` 保留原命令，恢复后重试。
- 明确拒绝会结束对应 Promise；断线会保留 Promise，重连后的原 ACK 可完成它。
- 真正离房使等待者收到 `AbortError`，本机未确认记录仍保留。

这样每个成员仅保留一个回执，不需要无限增长的 ID 字典，也不会因删掉旧回执而让旧网络命令重新执行。规则引擎的阶段回执在进入新阶段时清理，仍由阶段序号和待结算操作保护。

## 踢出、替换与恢复

被移出的连接立即失去提交资格，随后收到终态通知；正常客户端收到通知后停止自动重连。自动恢复握手还携带已知成员 generation，房主在事务内检查原成员仍然存在，使丢失移除通知后的重连也不能自动创建新座位。

这不等于永久封禁某个人：返回首页后，用户可以按仍然有效的邀请明确重新加入。持有公开邀请的人也可以创建新的本机凭证。此模型没有账号身份或永久封禁服务。

房主恢复继续使用原房间 ID、成员凭证和命令序号。进行中的房间先暂停，等待所有原成员在线后再继续。新邀请只更新信令目标；客户端设备自己的 ICE/TURN 配置继续由本机保存。

更换邀请和离房会取消当前建联尝试。即使底层回调已排队、取消后才返回 Peer 或 Link，控制器也会关闭该旧资源，不能把它写入新会话。所有临时监听、重连计时器和房主写锁均按所属会话清理。

## 输入与资源边界

| 边界 | 当前约束 |
| --- | --- |
| SDP | 必须有匹配的类型及非空字符串，最多 65536 个 UTF-16 码元 |
| ICE 候选 | 校验字段类型/长度；每连接最多 64 个 |
| 未完成协商 | 自创建起 20 秒绝对期限；流量不能延长 |
| RTC 连接 | 最多 20 个，同一来源最多 2 个未建立连接 |
| 早到候选缓存 | 最多 24 个连接键，每键最多 64 条，20 秒过期 |
| 信令待发队列 | 最多 128 项，关联具体连接，20 秒过期；关闭连接即清理 |
| 数据通道帧 | 字符串长度不超过 60000；仅接收 JSON |
| 分片消息 | 每片入队前累计不超过 512000 个 UTF-16 码元；ID 1–96 字符；顺序、end 类型严格校验 |
| 发送积压 | 最多 256 帧，按 `bufferedAmount` 背压发送 |
| 房间握手 | 数据通道接受起 30 秒绝对期限，心跳不能续期 |
| 主机连接 | 最多 20 条已接受数据链路 |
| 单连接消息 | 突发容量 30，每秒补充 10，反复超限关闭 |
| 单成员命令 | 突发容量 6，每秒补充 2，跨连接保留速率状态 |
| 全房间工作 | 突发容量 40，每秒补充 10 |
| 在途工作 | 每连接一个命令；房间事务队列最多 64 项 |
| 回执 | 每成员仅一条，受单调序号保护 |
| 聊天 | 每条最多 400 字符，保留最近 80 条 |

这些约束用于限制单个房间的资源占用和重试行为，不能保证浏览器房主或公共信令服务在所有网络条件、恶意流量下始终可用。

客户端接收房主消息时重建完整 DTO，递归校验数字、枚举、数组和嵌套字段。页面仍对所有网络来源的文本进行转义，包括协议本应保证为数字的座位号。规则信任房主不代表允许房主提供 DOM 标记。

## 聊天与语音

聊天草稿仅在 ACK 后清空。等待期间继续编辑会递增草稿 revision，旧 ACK 不会清掉新输入，即使用户修改后又写回相同文字。明确拒绝保留草稿供修改。新版本的旧操作归档只展示操作内容，不展示凭证。

`VoiceRoom` 用麦克风请求代次区分当前请求。`stopMic` 和 `close` 立即使旧请求失效；稍后返回的 `getUserMedia` 流会停止全部轨道，不重新绑定。旧请求的完成回调也不能覆盖更新的请求状态。

音频混音目标的创建与发送音轨绑定分别记录状态。`replaceTrack` 失败后，重新启用声音会重试绑定；替换进行中不会并发重试，成功后不重复替换。端点移除、替换或房间关闭后，迟到的音轨绑定及远端播放失败不能写入当前房间的错误状态。

房主按规则决定可发言成员，在监听和转发增益处都执行门控。每位客人收到排除自身声音的混音。移除成员时清除该座位的禁言状态，新加入者不会继承前一个成员的限制。

## 跨网络连接的范围

当前默认使用公共 PeerServer 信令与 Google STUN，未配置 TURN 中继。2026-10-12 使用独立 Linux 和 macOS 公网运行器、线上 v0.4.1 页面及原样默认设置的[实测](https://github.com/miiyakumo/touhou-chess/actions/runs/38262106611)通过了房间加入、双向聊天及持久化 ACK；所选连接为公网 UDP 的 `srflx` 候选对。已知非零麦克风输入在双方远端 WebAudio 节点中均测得非零样本，确认声音进入接收链路；这不包含扬声器或人耳听感验证。该浏览器的入站 `totalAudioEnergy` 仍显示零，不能仅依赖这个统计字段判定静音。

[较早一次实测](https://github.com/miiyakumo/touhou-chess/actions/runs/38259994005)在房间握手前连接失败；信令及 STUN 均成功，但证据不足以确定具体 NAT、防火墙或 DTLS 原因。后续成功不代表任意网络组合均可达。直接路径不可用时需要可用的 TURN 服务；当前邀请不会传递 ICE/TURN 配置，参与端需分别配置。验证 TURN 时应单独检查强制中继路径，以及限制 UDP 时的 TCP/TLS 中继，不以 STUN 成功或房主页面显示在线代替实际客机加入。

## 发布

`npm run check:build` 比对全部生成内容，并拒绝重复的 `public/hx.html`。PR 的 `Test multiplayer` 工作流运行生成检查、Node 回归和浏览器集成。Pages 的 `verify` 作业复用同一个工作流，只有通过后才组装和部署。

发布依赖仅用于测试。页面本身不加载 Playwright、ws 或 npm 包，也不增加在线遥测或新服务。
